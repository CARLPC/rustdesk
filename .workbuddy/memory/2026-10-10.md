# 2026-10-10

## RustDesk Windows Flutter 构建排查（`python build.py --flutter --hwcodec --vram`）

### 结论：非代码问题，是依赖环境问题

**P1 — 真正的编译阻塞：vcpkg 里的 FFmpeg 版本不对**
- 失败文件仅 2 个：`cpp/common/util.cpp`、`cpp/ffmpeg_ram/ffmpeg_ram_decode.cpp`（hwcodec 其余 ~18 个 `.o` 均已编译成功）。
- 手工用相同参数（MSVC 14.51.36231 + x64-windows-static + `-MT -O2 -Brepro -W4 -DNOMINMAX -DMFX_DEPRECATED_OFF -DMFX_D3D11_SUPPORT`）复现得到的真实错误：
  - `util.cpp(59): error C2065: 'FF_PROFILE_H264_HIGH' 未声明的标识符`
  - `util.cpp(61): error C2065: 'FF_PROFILE_HEVC_MAIN' 未声明的标识符`
  - `ffmpeg_ram_decode.cpp(218): error C2039: "key_frame" 不是 "AVFrame" 的成员`
- 原因：`C:\vcpkg\installed\x64-windows-static` 装的是 **ffmpeg 9.0.2（libavutil 61）**，项目要求 **7.1.1**（`res/vcpkg/ffmpeg/vcpkg.json` 的 overlay 端口，含 RustDesk 自有补丁）。`FF_PROFILE_*`、`AVFrame::key_frame` 在 FFmpeg 7 之后已移除。
- `C:\vcpkg` 位于 commit `b3ae22a`（2026-09-29），CI/基线锁定 `9e593bb18ea69cc5095e012465dcd675a822ed0d`（2026-07-29）。已装端口全是 stock：ffmpeg 9.0.2 / aom 3.15.1 / libvpx 1.16.0 / libyuv / opus / libjpeg-turbo；**ffnvcodec、amd-amf、mfx-dispatch 未安装**。仓库内 `vcpkg_installed/` 为空（manifest 安装从未完成）。

**修复命令（须在普通终端执行）**
```bat
cd /d C:\vcpkg
git checkout 9e593bb18ea69cc5095e012465dcd675a822ed0d
bootstrap-vcpkg.bat -disableMetrics
cd /d F:\rustdesk
set VCPKG_DEFAULT_HOST_TRIPLET=x64-windows-static
C:\vcpkg\vcpkg install --triplet x64-windows-static --x-install-root="C:\vcpkg\installed"
python build.py --flutter --hwcodec --vram
```
建议先把现有 stock `C:\vcpkg\installed` 改名备份。预计需 30–60 分钟从源码编译 FFmpeg 7.1.1 + ffnvcodec/amd-amf/mfx-dispatch。

**P2 — 本会话（WorkBuddy agent）无法执行该构建**
- LiteSandbox 拦截 **Rust 创建「只写命名管道」（给子进程喂 stdin）**：`stdin(Stdio::piped())` 稳定失败，OS error 231 `ERROR_PIPE_BUSY`；stdout/stderr 管道正常；`dangerouslyDisableSandbox` 无效（`LSBOX_*` 变量仍在）。
- 最小复现：`Command::new("cmd").stdin(Stdio::piped()).spawn()` → 20/20 失败。原始 FFI `CreateNamedPipeW`(INBOUND/DUPLEX) 正常，仅 `PIPE_ACCESS_OUTBOUND` 的客户端连接被拒。
- 受害方：① `rustix-0.38.34` 的 build script（`can_compile` 把源码管道喂给 rustc stdin，`build.rs:245`）→ cargo build 必挂；② **vcpkg 本体（Rust 实现）解压归档**：`error: calling CreateFileW stdin failed with 231 ... while extracting 7z2603-x64.7z`。
- 因此 vcpkg 安装与 cargo 构建都必须在 WorkBuddy 之外的普通终端跑（用户贴出的 hwcodec 报错说明其已在外部终端执行）。

**其它**
- 网络出口是 WorkBuddy 本地代理 `http://127.0.0.1:57551`，对 GitHub release 资产不稳定（同 URL 一次 200、两次连接失败）；vcpkg 新工具要求 cmake 4.4.3，而锁定基线配套 cmake 4.3.0，进一步说明工具版本与基线需匹配。
- 排查期间临时改过 `%USERPROFILE%\.cargo\registry\src\index.crates.io-1949cf8c6b5b557f\rustix-0.38.34\build.rs`，已还原。
